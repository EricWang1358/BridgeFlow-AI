对照对象：[`07-prd-v0.1.md`](07-prd-v0.1.md) 的 FR 01–FR 26、核心数据模型、权限审计与非功能需求。
代码基线：`main` 分支首次脚手架提交。

**状态口径**

| 记号 | 含义 |
| --- | --- |
| ✅ | 已实现且有测试或可运行验证 |
| 🟡 | 骨架存在，但不满足 PRD 的验收标准 |

## 先说三个结论

**一、当前脚手架满足 PRD 的比例约为 25%，且集中在"算法主链路"，不在"可审计性"上。**
PRD 的重心是可追溯、可审批、可版本化——导入批次、映射版本、预警状态机、审批链、审计日志。这些在代码里**一个都没有**。四个 Agent 的骨架反而是相对完整的部分。这个偏差需要在排期上纠正：PRD 第十三章七条首版验收标准里，有四条考的是审计与追溯能力。

**二、有一个架构级冲突必须在写更多代码之前解决。**
`agents/evaluator.py:85` 把**全部标准化行**序列化成 JSON 塞进 LLM 提示词。PRD 第十二章要求单批次支持 20 万行。20 万行进不了任何模型的上下文窗口，也不可能在十分钟内完成。研判层必须改成"先按规则聚合出指标，再让模型解释指标"，而不是"把原始数据交给模型让它自己算"。这同时也是 PRD 第十六章"Agent 结论缺乏解释"风险的正解——规则算数字，模型写解释。**这个改动越晚做，返工面越大。**

**三、`Correction` 缺少来源定位，FR 06 与非功能"可追溯"目前无法验收。**
`schemas/__init__.py:36` 的 `Correction` 只有 `row` 和 `column`，没有文件名、工作表名和批次号。PRD 要求"任意结果可追溯到原始文件与具体单元格"。这是个小改动，但它是许多下游需求的地基，应该在 M1 之前做掉。

## FR 01–06 数据清洗与自愈

| FR | 状态 | 现状 | 缺口 |
| --- | --- | --- | --- |
| 01 多文件月度批次 | 🟡 | `api/main.py` 的 `/analyze` 接受 `period` + 多个 `(department, file)` | 无批次实体。缺上传人、上传时间、解析状态、失败原因、重试。批次是 PRD 数据模型的第一个对象，现在完全没有 |
| 02 识别六类质量问题 | 🟡 | `agents/sanitizer.py` 处理字段名规范化、日期格式混用、数字与文本混用、空行 | 缺三类：**列错位**、**重复行**、字段名拼写差异（现在只做 snake_case，`SKU_Qty` 与 `sku_quantity` 仍是两列）。质量报告不可导出 |
| 03 修复建议含五要素 | 🟡 | `Correction` 有原值、建议值、规则、置信度、理由 | 缺**影响范围**。缺逐项/批量接受与拒绝的接口，缺操作日志 |
| 04 关键字段禁止自动补全 | ✅ | 系统不做任何缺失值填充；填充率不足一半的行进入 `quarantine` 而非被丢弃或猜测 | 需显式定义"关键字段"清单（金额、客户、SKU、审批），并在下游结果上打**不完整标记**。当前 `quarantine` 只是隔离，没有向下游传播完整性状态 |
| 05 时间序列补齐与币种单位统一 | ⬜ | 只做了数值格式归一（去货币符号与千分位） | 完全缺失：按月补齐、补齐行标记、币种换算、单位换算、换算规则版本记录。样本数据里 `S$` 前缀现在被直接剥掉，**没有记录币种**——这是个隐患 |
| 06 保存原始文件与差异 | 🟡 | 差异记录在 `CorrectionLog` | 不保存原始文件。`Correction` 无文件名/工作表/批次号，无法定位到"具体单元格"。见上文结论三 |

## 权限与审计（PRD 第十一章）

⬜ **整章未实现。** 无用户、无角色、无鉴权、无审计日志。当前 API 任何人可调用任何端点。

这是 PRD 里体量最大的单块缺口，也是首版验收标准第 7 条的全部内容。需要单独排期，不能顺带做。

## 建议的处理顺序

PRD 的里程碑是 14 周的完整产品节奏，与当前的 hackathon 节奏不同。建议按"先修地基、再补功能"排：

1. **改 schema 地基**（半天，阻塞其余全部）
   `Correction` 加来源定位；`Finding` 加基线、阈值、影响；`Entity` 加来源与有效期；`Link` 加比例与生效月份。趁没有存量数据，改起来没有迁移成本。
2. **重构研判层为"规则算数、模型解释"**（结论二）
   这是唯一会推翻已有代码的改动，越早越好。
3. **引入批次与版本**
   导入批次 → 已发布结果版本 → 映射版本。FR 01、FR 11、可靠性、可追溯都挂在这上面。
4. **预警状态机与审批链**（FR 17、FR 20、FR 25）
5. **权限与审计**（PRD 第十一章，单独排期）
6. **导出与看板**（FR 19、FR 21）

## 需要业务方回答才能继续的问题

PRD 第十七章列了九条待确认。其中**阻塞开发**的是这四条，其余可以并行：

- **第 4 条（指标公式与阈值）** — 阻塞 FR 12–16 的规则化改造。没有公式就只能继续让模型猜，而 PRD 明确不接受这一点。
- **第 5 条（补全、换算、分摊的批准规则）** — 阻塞 FR 05 与 FR 08 的分摊比例，进而阻塞报价成本计算。
- **第 8 条（最低毛利、产能预留、信用额度、账期上限、审批链）** — 阻塞 FR 22–25 全部。
- **第 2 条（每月文件数量与最大行数）** — 决定研判层重构的目标量级。20 万行是 PRD 的建议值，需要确认是否真实。
