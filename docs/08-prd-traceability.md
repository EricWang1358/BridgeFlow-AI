# 08 — PRD 需求与代码现状对照

对照对象：[`07-prd-v0.1.md`](07-prd-v0.1.md) 的 FR 01–FR 26、核心数据模型、权限审计与非功能需求。

**这是一张快照，不是一份进度报告。** 代码基线是 `main` 的首次脚手架提交，也就是说它记的是
「四个 Agent 的骨架刚立起来时，PRD 的哪一条有影子」。现在的实现状态请看
[`17`](17-business-mvp-acceptance.md)（业务闭环能演示到哪）、[`16`](16-dsh-web-review.md)
（逐项验收条件）与 [`00`](00-status.md)（数字）。当时判为「缺失」的东西，一部分后来做了，
一部分被明确判定不计分而关闭（理由见 [`09`](09-rubric-assessment.md)）。

状态记号：已实现并有测试或可运行验证；骨架存在但不满足验收标准；未实现；与 PRD 冲突（要改而不只是补）。

---

## 当时先说的三个结论

**一、脚手架满足 PRD 的比例约 25%，且集中在算法主链路，不在可审计性上。**
PRD 的重心是可追溯、可审批、可版本化：导入批次、映射版本、预警状态机、审批链、审计日志。
这些在当时的代码里一个都没有，四个 Agent 的骨架反而是相对完整的部分。这个偏差需要排期纠正：
PRD 第十三章七条首版验收标准里，有四条考的是审计与追溯能力。

**二、有一个架构级冲突必须在写更多代码之前解决**（这条后来解决了）。
`agents/evaluator.py:85`（当时的行号）把全部标准化行序列化成 JSON 塞进提示词，而 PRD 第十二章要求单批次
20 万行。20 万行进不了任何上下文窗口，也不可能在十分钟内完成。研判层必须改成
「先按规则聚合出指标，再让模型解释指标」，而不是把原始数据交给模型让它自己算。
这也是 PRD 第十六章「Agent 结论缺乏解释」那条风险的正解：规则算数字，模型写解释。
后来按 #13 改掉，同一原则现在写成硬约束（`CLAUDE.md`「原始数据行绝不进上下文」）。

**三、`Correction` 缺来源定位，FR 06 与非功能「可追溯」当时无法验收。**
`schemas/__init__.py:36`（当时的行号）的 `Correction` 只有 `row` 与 `column`，没有文件名、工作表与批次号，而 PRD 要求「任意结果可追溯到原始文件与
具体单元格」。改动很小，但它是许多下游需求的地基。后来的形态是 `SourceRef`（`docs/03`）：
行列之外还带批次、文件、工作表与原件指纹。

## FR 01–06 数据清洗与自愈

| FR | 当时状态 | 现状 | 缺口 |
| --- | --- | --- | --- |
| 01 多文件月度批次 | 骨架 | `api/main.py` 的 `/analyze` 接受 `period` 加多个 `(department, file)` | 没有批次实体。缺上传人、上传时间、解析状态、失败原因、重试。批次是 PRD 数据模型的第一个对象 |
| 02 识别六类质量问题 | 骨架 | `agents/sanitizer.py` 处理列名规范化、日期格式混用、数字与文本混用、空行 | 缺列错位、重复行、字段名拼写差异（当时只做 snake_case，`SKU_Qty` 与 `sku_quantity` 仍是两列）。质量报告不可导出 |

| 05 时间序列补齐与币种单位统一 | 未实现 | 只做了数值格式归一（去货币符号与千分位） | 按月补齐、补齐行标记、币种换算、单位换算与换算规则版本记录全部缺失。样本里 `S$` 前缀被直接剥掉且不记录币种，是个隐患 |
| 06 保存原始文件与差异 | 骨架 | 差异记在 `CorrectionLog` | 不保存原始文件；`Correction` 定位不到「具体单元格」（见结论三） |

## 当时建议的处理顺序

PRD 的里程碑是 14 周的产品节奏，与三周黑客松不是一回事。顺序按「先修地基、再补功能」：

1. 改 schema 地基（当时估半天，但它阻塞其余全部）：`Correction` 加来源定位，`Finding` 加基线、阈值、影响，`Entity` 加来源与有效期，
   `Link` 加比例与生效月份。趁没有存量数据，没有迁移成本。
2. 把研判层重构成「规则算数、模型解释」（结论二）。这是唯一会推翻已有代码的改动，越早越好。
3. 引入批次与版本：导入批次 → 已发布结果版本 → 映射版本。FR 01、FR 11、可靠性、可追溯都挂在这上面。
4. 预警状态机与审批链（FR 17、FR 20、FR 25）。
5. 权限与审计（PRD 第十一章，单独排期）。
6. 导出与看板（FR 19、FR 21）。

后来的实际走向与前两条一致（架构归位优先）。3 到 6 中的一部分被判定不计分而关闭，
判断依据写在 [`09`](09-rubric-assessment.md) 与 [`13` 第六节](13-golden-standard.md)。

## 需要业务方回答才能继续的问题

PRD 第十七章列了九条待确认，其中四条当时阻塞开发：

- 第 4 条（指标公式与阈值）：阻塞 FR 12–16 的规则化改造。没有公式就只能继续让模型猜，而 PRD 不接受。
- 第 5 条（补全、换算、分摊的批准规则）：阻塞 FR 05 与 FR 08 的分摊比例，进而阻塞报价成本计算。
- 第 8 条（最低毛利、产能预留、信用额度、账期上限、审批链）：阻塞 FR 22–25 全部。
- 第 2 条（每月文件数量与最大行数）：决定研判层重构的目标量级。20 万行是 PRD 的建议值，需要确认真实性。
