# 17 — 业务用例设计 MVP 验收与演示

> 当前演示范围与未完成项以 [链路审计](19-chain-audit.md) 和 [最新状态](00-status.md) 为准。正常案例可展示；人工意见禁止重跑、完整超时及重启恢复尚未完成，不能将下方流程说明当作稳定 MVP 的全项验收。

本次交付可以用于向业务用例设计负责人演示“导入 → 规则计算 → 部门独立研判 → 人工决定 → 可重开报告”的工作方式。数据是透明生成的制造企业案例，验收针对这条月度闭环；不等于真实企业上线、正式财务报表签发或 rubric 全项满分。实测结果、时延、调用量与证据统一见 [00](00-status.md#业务-mvp-sprint-验收2026-09-06)。

## 验收口径与责任

这里由开发代理**模拟业务负责人进行审查**，核对可复算结果、部门权限和模型原文。没有冒充真实部门负责人签字。业务方仍须确认自己的字典、单据粒度、成本符号、币种、信用规则及成功判据。

| 部门 | 应交付的判断 | 计算依据 | 谁决定下一步 | 禁止越过的边界 |
| --- | --- | --- | --- | --- |
| 生产 | 工时负荷、剩余工时 | 声明的实际工时与可用工时 | 运营负责人 | 分析员不批准加班预算、不承诺客户交期；每条班次的可用工时只能登记一次 |
| 采购 | 实际支出、同数量预算价格偏差 | 逐行单价乘数量，随后求和；禁止把单价相加当支出 | 采购负责人，涉及预算时联同财务 | 不改销售报价；缺价、缺量或币种不符时拒绝计算 |
| 财务 | 项目毛利、余额加权账期 | 收入与正数成本独立列；应收余额作为权重 | 财务负责人 | 不将净发生额称收入；不能从毛利或平均账期推断减值、坏账或信用趋势 |
| 市场 | 同期订单与产出差额、数量加权请求账期 | 总量比较与声明权重 | 销售负责人；信用条件交财务审批 | 总量充足不等于品项齐套；不生成客户 Tier、价格带或自动承诺账期 |
| 协调者 | 汇集有效判断、列出责任和未完成部门 | 官方子会话结果及后端校验 | 业务负责人协调，人裁决冲突 | 不把部分失败写成成功，不执行采购、排产、报价或授信 |

`risk` 触发声明的关注条件；`balanced` 回到正常范围。标准答案在 [expected.json](../data/business_demo/expected.json)，由生成器独立显式算术产生，应用的公式求值器不参与生成答案，模型也不接收答案文件。该测试组属于**可见开发/演示集**，不是留出评测集；本 sprint 没有读取 `data/acceptance/`。

一站式文件入口见 [demo-walkthrough](../demo-walkthrough/README.md)，页签与轻量文件栏设计见 [18](18-native-captain-and-state.md)。

## 演示准备

在仓库根目录，先按 [HANDOFF](../HANDOFF.md) 安装锁定的 Python 与 DSH npm 依赖。使用独立演示目录，避免把合成映射写进自己的业务记忆：

```bash
source ../.venv/bin/activate
source ./env.sh
python scripts/make_business_case.py
export DSH_HOME="$(mktemp -d /tmp/bridgeflow-demo-dsh-XXXXXX)"
export RESULT_STORE_PATH="$DSH_HOME/business-output"
export MAPPING_MEMORY_PATH="$DSH_HOME/mappings.json"
export FIELD_DICTIONARY_PATH="$PWD/data/business_demo/dictionary.yaml"
pnpm --dir plugins run build
python scripts/start_web.py --port 3082
```

打开启动器打印的认证地址。此处使用默认原生 Web，不启用 `/console`。导入不调用模型；在聊天中提交请求会使用 shell 配置的真实模型。

## 台上操作

1. 从「导入与数据」或右上角「部门文件」选择并导入 `data/business_demo/risk/` 下各部门 CSV，月份与 [案例说明](../data/business_demo/README.md) 一致。解释待确认映射与隔离行的区别；未确认映射不被本次直接列汇总计算消费。
2. 复制研判请求，在原生工作区 `BridgeFlow` 的会话中发送。观察 `review_context → 同一响应四次 subagent → review_finalize`、轨迹四次 Spawn 与顶栏四个子代理；每个部门有自己的会话编号和结构化结果。
3. 点「对话｜轨迹」右边的「业务状态」页签，再打开「四部门报告」，看部门负责人、风险方向和建议；公式直接显示，展开一项“解释与原始来源”，沿文件、原始行号、原始列名核对。来源展示封顶不代表只用样本算数。
4. 在相同演示环境导入 `balanced/` 为新批次，再次研判。比较风险方向，重开旧批确认它没有被覆写。不要声称正常范围就代表所有风险消失。
5. 展示映射审批时，明确工具的 `accepted=false` 是“记录一项否定关系的决定”，仍需批准写入；审批面板的“拒绝”则是**不执行这次写入**。两者不能混称。
6. 在会话中要求对指定合成关系调用一次 `confirm_mapping`，填写可选拒绝理由再拒绝。模型应解释未写入并转述理由；未来导入仍可能询问。批准才记录记忆。审批日志与记忆文件结果由自动复测核对。

隔离修复演示使用源文件副本：把日期改为歧义格式，导入后报告应拒绝；修正源文件再导入新批次恢复。当前没有隔离 release/discard 或字段映射向导，不在台上假装存在这些按钮。

## 自动复演

```bash
# 不调用付费模型：完整原生浏览器及故障路径
cd plugins
pnpm run smoke:web
pnpm run smoke:business
BRIDGEFLOW_CASE=balanced pnpm run smoke:business
BRIDGEFLOW_TEST_FAULT=step-limit pnpm run smoke:business

# 真实模型：从根目录 source env.sh 后运行
BRIDGEFLOW_LIVE=1 pnpm run smoke:business
BRIDGEFLOW_LIVE=1 BRIDGEFLOW_CASE=balanced pnpm run smoke:business
BRIDGEFLOW_LIVE=1 pnpm run smoke:web
```

每次脚本创建临时 DSH_HOME、私有服务凭证、批次输出和映射记忆，并关闭自己启动的服务。终端输出证据目录；业务测试保存报告、截图、测量 JSON 与原生 JSONL。审批测试保存成对决定、拒绝备注和实际模型叙述。真实模型输出没有经过离线适配器替换。

失败路径包括：缺价、币种不符、符号不符、零分母、歧义日期、重复行交易身份不明，以及模型篡改数值/单位/状态/动作、讨论明确禁止的财务命题。子会话连续输出无效结构时触发步骤上限，整体标 `partial`，该部门没有伪造的兜底判断。partial 页可向原队长提交人工复核意见，不替缺失部门签字，也不强制重跑整组。

## 本次发现并修正的问题

- 官方审批默认值只有决定枚举，没有备注字段。通过官方 `conversation.composer` slot 增加映射专用呈现；仍调用官方 `pending.answer`，不更改官方审批服务或 fork DSH。备注先走同源鉴权、当前会话与调用绑定的临时票据，再进入原生会话审计及既有拒绝反馈。备注不授予写权限。
- `list_metrics` 的 Python 返回包含内部计算配置，而 TS 公共输出禁止额外字段。工具壳现在显式投影公共字段；浏览器测试在真实派发中执行目录和聚合，正常用例禁止隐藏工具错误。
- 拒绝反馈原文只说“不记住”，真实模型曾误说下月不再询问。现在明确“未来仍可能询问”，真实模型复测核对叙述与文件。
- 正毛利曾被真实模型扩写为“无需计提损失”。收紧解释任务，并对字典声明的禁止命题执行校验；不把规则通过当作开放文本语义正确的完整证明。
- 旧去重会删除相同行。业务总额现在在出现该修正时拒绝，要求先核实交易身份；原始行号在去空、去重、隔离后仍可追溯。

## 还差什么

业务用例设计演示可以开展。进入真实企业试用仍需要：真实 OA 字典和脱敏单据验收、员工身份与角色/租户边界、字段配置及隔离处置、版本差异与签发流程。平均指标可能掩盖单客户风险；当前没有客户级信用规则、库存/BOM 齐套模型或动态报价依据。普通聊天叙述是模型解释，正式数值和权限结论以报告的校验字段为准，不能将它直接签发为财务报表。

远端看板建议见 [16](16-dsh-web-review.md)：把本地证据用于评审，不以卡片数量或采用某个 DSH 包换算 rubric 完成度；本次没有修改远端 issue/看板。
