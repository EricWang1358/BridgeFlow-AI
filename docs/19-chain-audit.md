# 19 — 跨操作链路审计与修复

这轮检查针对“页面存在、单次脚本能跑，但连续操作仍出错”。结论是：批次、研判运行、报告、会话、审批的身份与结束条件没有贯穿全部入口。正常样本跑通不能替代切换、取消、断网和重启验收。具体实测数字统一见 [00 最新补充](00-status.md#跨操作链路复查2026-09-06当前结论)。

## 实际链条与责任

```text
启动器 → 官方 DSH Web → 同源鉴权代理 → 私有 FastAPI
                                 ↓
本地 CSV/XLSX → 导入/字典/清洗 → 不可变 batch_id
                                 ↓
review_context → review_id + 父会话 + 四个角色票据
                                 ↓
父模型同一响应四次官方 subagent → 四个真实 child session
                                 ↓
structured_output → 宿主收集 → Python 按冻结字典校验
                                 ↓
report_id（validated / partial）→ 报告卡 / 弹窗 / 业务状态页

confirm_mapping → 官方审批 + callId / approvalId → 一次性回执 → mappings.json
                                                        ↓
                                                   后续新导入
```

| 身份 / 状态 | 权威来源 | 不能推导出的含义 |
| --- | --- | --- |
| batch_id、导入状态 | Python 不可变批次快照 | 不等于本次会话、最新研判或已批准 |
| review_id、派活状态 | 宿主生命周期与 bridgeflow/review 事件 | 工具调用尝试不等于成功 Spawn；事件未结束不等于仍在运行 |
| parent / child | 官方会话头与目录 | 切换批次不能借用另一单的派活数 |
| report_id、validated / partial | Python 保存的特定报告 | 最新历史报告不能填补当前运行；validated 不是业务签发 |
| approvalId / callId、审批决定 | 官方 asked / decided 及一次性回执 | 会话审批累计不是所选批次的批准状态；批准不改旧快照 |
| attention / 正常 | 已校验报告中的关注阈值比较 | 不是已执行采购、调价、授信或签核 |

导入 needs_review 与报告 validated 可以并存：本业务案例直接计算声明列，不依赖待确认的跨部门关系；有隔离行或配置拒绝则禁止研判。因此实际实现不是一条简单的 `ready → validated → approved` 流水线。界面需要分清各自作用域，不能用一个绿色状态表示整条业务链完成。

## 已复现并修复

| 故障 | 根因 / 修复 | 验证边界 |
| --- | --- | --- |
| 从 A 的特定报告导入 B，B 报告请求仍带 A 的 report_id | 上传清除报告身份，并统一写批次路由 | 同一浏览器、同一会话连续上传两批；修复前返回错误的“报告不属于该批次”，修复后提示尚无报告 |
| 手选 B 后点刷新，跳回 A | 刷新不再清除选择；“跟随当前会话批次”成为单独操作；监听状态页路由 | 浏览器断言刷新仍为 B |
| B 显示 A 的四次派活 | 按所选批次约束派活记录，注明是工具派发尝试；审批另标当前会话作用域 | 浏览器跨批次断言与投影测试 |
| 不存在的批次链接仍展示旧批次、加载提示与错误并存 | 切换时清空旧内容与成功提示、取消未完成请求、错误后停止加载提示 | 浏览器访问合法格式但不存在的批次 ID |
| 同批次新研判仍加载旧成功报告 | 以 review_id / report_id 选择本次结果；本次没有汇总时不请求历史 latest | 投影回归测试；未声称完成真实模型连续重跑验收 |
| 前端改过但启动仍展示旧包 | 启动前检查客户端源码、构建脚本及锁文件是否比产物新；给出构建命令 | 临时目录测试缺失、过期、有效产物 |
| 后端退出而 Web 继续挂着；Web 异常退出被启动器当成功 | 启动器监视两进程并传播失败，通过已有 finally 清理自身子进程 | 模拟进程退出测试；未做真机中途杀进程演练 |
| 坏 YAML / 字典结构让导入返回泛化 500 | 配置读取与字典构建异常返回明确 503，要求管理员修复；不落盘猜测结果 | 修复前用 TestClient 复现；修复后覆盖语法、根类型、字段结构、关系缺字段；缺字典原有语义保留 |
| 报告、计量已写出，但后面的 UI 断言失败 | business smoke 在全部断言之后写 acceptance.json；失败明确 passed=false；采集器保留该结果 | 采集测试确保失败标记不会被转换成通过；旧证据缺此文件不补造通过标记 |

浏览器回归现在默认包含跨批次操作，不再需要额外开关；step-limit 故障场景单独执行。修复前后证据作为同一场景保留，最多两轮：

- [修复前失败明细](evidence/business-mvp/chain-regression/runs/1788700374086086706/chain-audit.json)
- [修复后连续操作明细](evidence/business-mvp/chain-regression/chain-audit.json)
- [修复后最终验收结果](evidence/business-mvp/chain-regression/acceptance.json)
- [仅对应父子会话的审计](evidence/business-mvp/chain-regression/session-audit.json)

这些是离线模型适配器驱动的真实官方 Web、工具派发和浏览器操作。它们验证交互和协议；不代表本轮重新付费验证了模型表现。之前真实模型的费用与延迟基线保留，未被本轮离线数据覆盖。

## 尚未完成的收尾链路

以下为代码审查确认的实现缺口；没有把尚未做的故障注入写成实测失败。

| 优先级 | 缺口与位置 | 下一轮必须给出的验收证据 |
| --- | --- | --- |
| P0 | partial 人工意见通过 `ui.ts:sendHumanNote` 提交普通聊天，禁止重跑只是文本要求；没有宿主级操作限制 | 让测试模型故意请求 review_context / subagent / 写工具，实际派发必须被拒；意见有持久记录且不改变报告校验状态 |
| P0 | `review-batch.ts` 的超时只中止组合进 subagent 调用的 signal；父模型等待与结束回复不受完整期限约束 | 父模型卡在派活前、子模型卡住、汇总请求卡住分别注入；到期终止并形成明确可读终态 |
| P0 | `ReviewPolicy.states` 只在内存中；重启后已持久化的 dispatching 事件无法还原运行；`finish()` 缓存失败 promise 且没有失败终态事件 | 汇总前重启、服务暂时失联、响应丢失重试；有可恢复或明确失败的状态，且不会重复签发报告 |
| P1 | 配置里的输出 token 上限是单次模型请求上限，不能宣称整名子代理全部步骤共用同一额度 | 跨步骤累计预算及强制停止测试；分别记录父编排、子步骤与汇总成本 |
| P1 | 拒绝备注先写独立事件、决定后提交；多窗口竞争或超时边界可能留下未成为最终拒绝理由的备注 | 两窗口相反决定、备注写入后超时；审计区分备注草稿与最终决定，不把草稿称为最终拒绝原因 |
| P1 | 父子会话链接失败仅记客户端 logger，页面没有明确失败提示；状态页 URL 与原生页签激活也不是同一个操作 | 不存在的 parent/child、刷新及浏览器前进后退都有可见结果；不靠操作原生 DOM 强制切页 |

P0 表示会影响“本次业务操作是否完成”的可信度，必须在稳定演示验收前收尾，不是说已证明存在越权写入。审批回执、领域拒绝、角色校验的既有保护与上述恢复缺口分别评估。

## 应怎样重新验收

先完成运行时收尾契约，再做一次连续操作验收：导入 A 并研判 → 导入 B 但不研判 → 来回切换 / 刷新 / 深链接 → A 第二次研判 → 子步骤失败 → 人工意见且模型故意违令 → 审批拒绝与超时 → 汇总断网 / 宿主重启 → 明确恢复或失败。

每一步核对 batch_id、review_id、report_id、parent/child 和 approval/call 的归属，检查页面显示、落盘内容和真实调用是否一致。测试最终退出状态、acceptance.json 和证据清单必须一致。当前只完成表内标出的修复与验证，不能据此关闭以上 P0 或把模拟意见算作部门负责人签核。
