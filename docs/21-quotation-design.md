# 21 — 报价声明与文本证据边界

这份设计先于实现写定。报价与月度对账并列，共用声明式算术、SourceRef 与官方 DSH Web。
真实输入格式、正式报价模板与部门负责人仍待业务样板确认。实现范围对应 [任务书](20-quotation-brief.md)
的样板前阶段，实测与费用只记在 [状态文档](00-status.md)。

## 自由文本：先抽取，再推理

原始合同、客户会话与明细表留在受控存储里，不能作为报价工具参数，也不能整份注入上下文。
未来的适配器先识别文件结构与定位，再按人工字典给出的封闭候选集提取付款条件、数量、单价、交期等事实。
文件格式、分段方式与解析方法都等样板，这一轮不做假定。

适配器内部的交接对象是一个结构化事实集：声明字段标识、规范值、声明单位、抽取状态与 SourceRef。
它既不是客户上传的格式，也不是允许浏览器或模型自证真实的数据接口。本轮只用合成事实验证，
不开放自由文本上传，也不接受「用户提供一份 JSON 就算抽取成功」。

SourceRef 沿用现有形状，为文本增加定位：原文件名称、内容摘要、页或段、有限长度的原文片段。
文本引用不伪造表格的行与列。后续抽取器必须验证片段确实属于对应原件，并保留值规范化的依据。
带引用不等于抽取正确：本轮验证的是引用完整性与绑定关系，不是原文语义核验。

以下情况明确拒绝：抽取不完整、候选冲突、单位不符、来源缺失、原件版本冲突、超出容量。
未知输入不能自动创造字典条目。不用置信度替代缺失证据，不从采购合同臆测完整生产成本，
不从客户自述推断付款历史。

付款与交付条款里的触发点、条件与例外必须保留原样，不能把一条条件性条款压成一个天数。
样板阶段如果现有声明表达不了原意，就拒绝，不要套用本合成案例的天数示例。

推理层只拿到有界的结构化结果、计算公式、出处样本与真实的引用计数：字段数、公式深度、事实数、
片段长度都有上限。「大文件被截断」不能冒充「完整抽取完成」。原文片段仍然是非可信数据，
读它不改变任何工具权限。报价算术不调用模型。

## 声明与算术

新增一份独立合成示例字典的 quotation 段，沿用 business_review 的结构：inputs、roles、metrics、
checks、责任人与公式。真实字段名、单位、成本构成、利润规则、阈值与决策责任只出现在人工声明里。
这份示例用来证明执行契约成立，不是已获业务批准的报价政策，也不会被默认装载为生产字典。

共享的 business.expression 扩展为可读已验证的结构化事实，以及同一契约中已声明的指标引用。
继续用封闭运算符：不 eval、不猜列、不创建报价专用的价格算法。成本与价格用 Decimal 计算，
币种不做隐式转换，舍入方式由声明明确指定；金额序列化为十进制字符串，避免经过浮点数失真。

数值字段必须依赖真实输入证据，纯常量的报价不能通过。政策系数是字典声明的，不能冒充合同事实：
系统同时给出冻结字典的指纹与声明位置，数据出处仍然走 SourceRef。输入版本与契约指纹绑定到草稿上，
后续样板阶段接入现有的不可变批次存储；已保存批次的月度含义不因报价改动。

## 拒绝与批准的边界

先验证全部必需输入，再聚合成一次返回所有缺失项，重点是成本、可用产能与付款历史。
拒绝结果包含稳定原因码、声明字段或检查标识、可读名称、该由谁补充证据或决定，且不夹带半成品价格。
公式循环、除零、非有限数、未声明指标、缺少责任定义，一律拒绝。

产能或付款历史超过声明的关注阈值时，按声明阻止出数；阈值本身不是业务批准。
成功也只生成内部草稿，不代表已批准、已外发，或系统完成了某个业务动作。本轮不提供外发入口；
后续接现有的官方审批、回执与理由通道，不新增第二套审批。

## 原生界面

界面按用户提供的 NotebookLM 截图定制整个原生工作面：左侧 Sources 保存实际上传的文件，
中间始终保留 DSH 的原生会话、输入框、轨迹与审批，右侧 Studio 上方是可用工具、下方是持久化产物列表。
点击来源或报告在 Studio 里预览，也可以显式展开阅读。报价声明属于工具预览，
不能混进已上传来源或已生成报价。

实现上保留官方 AppFrame 及其全部槽与状态存储，只用官方 shell.overlay 增加两侧面板，
用宿主公开的 data-slot 样式锚点调整外层几何与主题。不替换根注册、不复制宿主私有组件、
不移动原生 DOM：直接覆盖 root 会遮蔽原生会话。会话与设置收进原生导航抽屉；
顶栏「新建笔记本」调用官方 sessions.create 创建独立会话并清空当前来源选择，
这与宿主「新建会话」复用空会话的既定语义是两回事。空会话可以直接打开 Studio 里的报价声明，
不必依赖被宿主隐藏的会话页签。月度数据工作区与业务状态页保留，不新增报价会话页签。

交互参考了 better-sidebar 的「预览与聊天并存」，但没有引入它的终端、编辑器、侧聊、任意路径读取
或其它插件代码。预览已有的 CSV 与单工作表 XLSX，用本项目受鉴权的批次只读接口就够了；
报价原件的格式还等样板，不预先造解析器。

上传时在独立的浏览器来源存储里保留清洗前的表格解析视图，以及文件名、工作表与原件内容摘要；
来源清单另存元数据，打开列表不加载整批明细。来源正文既不加入 BatchSnapshot，也不进入模型工具返回。
只读预览按批次、部门与页码定位；旧批次没有保存原件时明确显示不可预览，不用清洗结果替代。
Studio 的报告列表只读实际保存的报告身份，预览沿用原 BusinessReview 与证据组件。
切换批次、会话与预览时取消旧请求，避免残留报告与来源串批。

中英文标签、深浅主题、窄屏侧面板、键盘开关、分页原件、原生输入框身份、父子会话导航与审批，
都纳入隔离浏览器回归。截图按保留策略归档，所有实测数字只记在状态文档里。

## 笔记本的生命周期与状态归属

笔记本创建时通过官方 workspaceId 归入 BridgeFlow 工作区，保存时确认原生工作区成员关系，
原生输入框因此不需要再手动选目录。它复用原生会话的身份、标题与列表，插件只记录名称、用途、批次
和预览位置。用途可以是月度对账、报价或综合工作；右侧业务状态与原生状态页随用途调整，
但不能把「报价配置已就绪」显示成「报价已完成」。重复点击工具时保持打开与选中状态，
来源、工作室与原生导航按钮要反映实际展开情况。栏宽支持拖动、键盘调整与重置，布局偏好只存在浏览器里。

显式保存要等原生标题落盘与官方 storage-domain 写入完成，成功之后才显示「已保存」。
新建、退出或从笔记本列表切换时，只要名称、用途或来源改过，就提示保存、放弃或取消；
没改过的空笔记本不多问一次。放弃只丢弃笔记本编辑，不删除宿主已记录的对话、上传文件或报告。
原生会话抽屉保留宿主的切换语义；同一页面里的临时编辑算草稿，不冒充已落盘内容。
保存失败时保留当前页面与输入并提供重试。

笔记本列表用原生的普通会话目录：包含已经命名但还没发消息的笔记本，排除部门子会话。
恢复用服务器保存的书签；浏览器刷新与完整宿主重启都在回归范围内。原生会话事件持续保存，
笔记本不是另一套聊天数据库。

示例入口明确导入合成的部门数据，走现有清洗与规则计算，冻结示例字典而不改变部署中的字典。
来源可预览，规则主表出现在产物栏；报告只有实际研判并保存后才出现。示例导入不提交模型请求，
发起研判仍然是用户明确点击的动作。报价的真实样板还没到，不用合成 CSV 充当合同解析演示。

## 原生日志与插件元数据

锁定版本的 Session.append 不能给下游自定义事件设置可忽略标记，而原生冷读取器会拒绝未知的必需事件。
因此不向会话日志追加自定义的笔记本、研判或审批备注事件：笔记本书签与拒绝备注存在官方 storage-domain，
研判状态从实际的原生工具调用与结果投影出来，拒绝理由同时进入原生工具的拒绝结果。
备注按会话与调用身份绑定；存储键使用组合身份的摘要，以符合官方逐记录存储的约束。

历史上的 bridgeflow/review 与 bridgeflow/approval-note 只是信息性元数据。如果旧日志因此无法冷读，
可以先停机，用 scripts/repair_session_metadata.py 检查，确认后再显式应用兼容标记。
该工具会保存原始字节备份，只把已知信息事件标为可忽略，不改领域数据、事件内容、顺序或模型用量，
也不触碰其它未知必需事件。正常启动不自动改写或剪裁用户日志。

## 验收边界

合成事实加声明能生成带证据的草稿；移除任一必需依据、改错单位、损坏出处或制造公式错误都必须拒绝；
字段整体重命名后，只更新声明与合成事实即可继续运行；月度对账用例照常通过。
浏览器只验证实际可用的契约查看与布局，不把空页面算作「合同抽取」或「报价外发」已交付。

数据工作区弹窗单独注册在官方 shell.overlay，侧栏只注册打开入口。不要把会让页面进入模态的组件
放在可隐藏的侧栏祖先之下：这条是踩过坑的（隐藏祖先会让弹窗边界成为 0 × 0，原生模态同时锁住其余页面，
而控制台仍然 0 条 JS 异常）。功能验收必须确认弹窗真实可见、关闭后还能继续操作，
不能以「没有 JavaScript 异常」代替。来源信息要能解释文件与批次身份：单页无需翻页，
多页要验证双向内容变化。
