# 产品扩展契约

本次重构针对实际断链：诊断话术要求调用 `profile_batch`，工具也已经注册，但独立白名单遗漏了它，主机因此拒绝调用。另一处重复是笔记本用途：保存校验、下拉选项、Studio 与原生状态页各自维护用途分支，报价页提前返回 JSX 时，月度数据 hooks 仍然会执行。

架构边界仍以 [黄金标准](13-golden-standard.md) 为准。月度与报价并列，DSH 拥有会话、工具执行、审批与子代理；数据字段、公式和业务政策来自人工字典。验证结果、计量和费用只记 [实测状态](00-status.md)。

## 用途是能力组合，页面负责组合视图

`plugins/src/notebook-capabilities.ts` 是用途声明的唯一来源，提供名称、标签键和所含工作流。存储校验、用途选择器、Studio 进度与原生状态页共同消费它。

这里使用 Registry 与 Strategy：用途决定选择哪些工作流，视图注册表决定如何呈现。状态页按工作流挂载独立组件；报价用途不挂载月度 hooks，因此切换批次时不会为隐藏的月度报告发请求。旧笔记本缺少用途时沿用综合工作默认值，未知或可通过字符串转换伪装的用途不能写入存储。

新增已有工作流的用途组合，只扩展用途声明与文案。新增真正的业务工作流，还需实现其进度和完整视图，在对应注册表登记，并验证自己的数据契约；不修改 Shell 的条件分支或笔记本存储解析器。不要为了理论上的扩展写一套任意插件加载器。

用途控制呈现和指引，不是权限。切换到报价不会授权写映射或外发报价，也不会把声明模板变成交易产物。

## 工具在定义处携带执行政策

`withAccess(defineTool(...), access)` 将官方工具定义和本产品的访问契约放在一起，`ToolCatalogue.register` 同时登记工具与授权事实。组合入口仍明确决定安装哪些工具，默认拒绝未登记的领域工具。没有契约、契约不完整、名称重复或注册失败，都不能留下授权；卸载时同时撤销注册与政策。

| 契约 | 适用范围 | 执行边界 |
| --- | --- | --- |
| `read` | 有界只读查询、结构统计 | 不请求人工签字；仍受主机 guard 与后端鉴权限制 |
| `review` | 创建研判上下文、校验并保存系统报告 | 明确是研判生命周期，沿用运行身份、角色与子代理 guard；不代表业务批准 |
| `approval` | 需要人决定的业务写入 | 必须声明决定说明、拒绝影响和回执绑定的请求体，复用官方审批与一次性回执 |

这里使用声明式 Policy 与依赖注入。审批 gate 接收本次安装的目录，不再维护 `MUTATING_TOOLS`，也不再知道映射特有的请求体和“下月记忆”文案。新增业务写工具提供自己的契约即可；审批状态与最终拒绝规则保持共用。

契约不能凭空证明工具无副作用：开发者仍须审查 `read` 是否真的只读、`review` 是否只保存系统计算结果，以及新业务写接口是否核验对应回执。后端校验、参数绑定、一次性消费与真实派发测试不能因前端或 TypeScript 声明而省略。当前没有新增任何业务写动作。

原生 `subagent` 与 `ask_user_question` 由 DSH 安装，保留显式的部署许可。部门子代理仅能提交 `structured_output` 的终局限制独立存在；注册新父工具不会扩大子代理权限。

## 验证的是扩展行为

新增测试实际派发诊断工具，验证它到达后端协议边界；测试不完整声明、重复安装、卸载撤权，以及新增动作使用自己的审批说明和拒绝语义。旧的 Python 源码字符串清单断言由这些执行测试替代，Python 仍负责回执与领域写入的接口验证。

浏览器连续切换报价、月度、综合用途，并在报价状态中换批次，核对实际挂载组件、月度报告请求及恢复后的报告。保留来源分页、主表可关闭、保存重开、原生审批和实际子代理派发回归。离线协议验收不代表真实合同抽取、业务定价政策或部门负责人签核。

本次没有完成在途恢复、完整运行期限、partial 意见的宿主防重跑或并发备注结算；这些仍按看板独立跟踪，不能以采用设计模式为由标记完成。
