# 24 — 2026-09-13 团队讨论：定位收窄与协同的做法

> 决策记录。原始材料是一段会议语音转写，识别噪声很大；这里只记和产品有关的结论，
> 求职、其他插件等题外话不记。「已定」指会上无人再反对；「待定」指需要再拍板，见文末。
>
> 它**修改** 2026-09-11 讨论的结论（总览 [#127](https://github.com/EricWang1358/BridgeFlow-AI/issues/127)），
> 不推翻：映射、人工审核、持久化照旧；变的是「谁来建数据平台和权限」。

## 已定

### 1. 不重建数据平台：我们是外挂的 Agent 工具

- 目标用户是**把四部门文件整合成总表、向老板汇报的那个人或临时小组**，不是全员。
  这类小组一般公司不设常驻部门，所以更需要工具把一次性的整合工作规范下来。
- 自建带权限的文件平台 / 数据中台被否决：外包报价 20～30 万、工期半年起，三周做不完，
  而且会让交付重点从 Agent 设计偏到后端工程。
- 价值主张不变：同样的输入每次得到同样的结果，省掉人工逐条核对；
  而不是「把文件丢给通用 AI 让它整理」——那样每次结果都不一样。

### 2. 协同靠接现成平台，不自造

- 文件存储与权限（精确到组、到「能看 / 能编辑」）交给**飞书或同类平台**，RBAC 在平台后台配置。
- 我们只做**一两个接口或一个小 MCP**，证明能接入企业平台、有扩展方向。
- 设想的流转：部门上传到平台 → 自动标记「已上传」→ 通知下游 → 下游让 Agent 去平台取文件，
  处理完再交给下一个部门。
- 与「本地跑完导出 CSV 发群里」的区别，会上的结论是：**Agent 能自己取到需要的文件**，
  这才真正省人力；只多叠一层平台、仍需人工挑文件导入，则没有区别。

### 3. 以上都是辅助功能，核心还没打磨完

核心是字典映射与四部门整合。协同、权限、定时运维都排在它后面。

## 对既有需求的影响

| 需求 | 9/11 的写法 | 9/13 之后 |
| --- | --- | --- |
| [#126](https://github.com/EricWang1358/BridgeFlow-AI/issues/126) RBAC | 在 DSH Web 前自建登录与账号 / 角色 / 部门体系 | **不自建身份体系**。文件可见性由平台权限决定；我们只保证 Agent 读到的范围不超出操作者在平台上的权限，并且服务端判定、越权留痕 |
| [#123](https://github.com/EricWang1358/BridgeFlow-AI/issues/123) 映射持久化「构成数据中台的一部分」 | 自建中台层 | 持久化照做，但**只存本工具自己的映射与审计**；原始文件的存放与分发归平台 |
| [#122](https://github.com/EricWang1358/BridgeFlow-AI/issues/122) / [#124](https://github.com/EricWang1358/BridgeFlow-AI/issues/124) 映射与审核 | — | 不变，仍是最高优先级；**被样例数据阻塞**（见下） |
| 新增 | — | 平台接入试点（飞书或同类），范围只到「取文件 / 回传结果 / 标记状态」 |
| 新增 | — | 样例数据：2 组调优 + 1 组留出测试 |

rubric 角度（依据 [`09`](09-rubric-assessment.md)）：完整 RBAC 权限矩阵属于产品完整度，不直接计分；
但第 5 项 Safety 考 least-privilege，「Agent 的读取范围受操作者权限约束」恰好落在计分项里。
这是支持「轻量权限、交给平台」这条路的另一个理由。

## 不做 / 推迟

- 定时运维（每月自动重跑、演示迭代过程）：要模拟多个月数据，这次不做，作为远景讲。
- 工作流梳理的持续升级：同上。

## 已核对的事实

- `docs/10-proposal.md` 里**没有**协同、协作或上下游流转的表述。若协同要当卖点，proposal 与 PPT 需补叙述。
- 公网在线 demo 目前**不可用**：部署流水线停在缺少生产 SSH 凭证，见
  [#138](https://github.com/EricWang1358/BridgeFlow-AI/issues/138)。

## 待定

1. 平台选飞书还是其他：免费版是否够用、是否要注册企业；考虑国内外可用性。
2. 协同是否写进 proposal / PPT 作卖点，做到「真接通一个接口」还是「只画架构图」。
3. 样例数据的交付日期——它决定主线何时能动。
4. 两边可用时间错开（周一至三 / 周三至五，加上 ISS 朝九晚五），是否固定一次需求评审时间。
