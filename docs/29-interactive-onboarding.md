# 29 — 页面内交互式引导

本轮沿用 React 客户端插件、`shell.overlay` 与项目自己的原生 `dialog`。没有新增依赖、第二个 React root、DSH fork 或原生 DOM 搬移。样例、计算、原件预览、下载和笔记本保存全部调用既有业务入口；教程不调用模型、审批工具或外部服务。

## 进入与复演

完成 [HANDOFF](../HANDOFF.md) 的环境安装后，从仓库根运行：

```bash
source ../.venv/bin/activate
source ./env.sh
pnpm --dir plugins build
python scripts/start_web.py --demo
```

打开启动器打印的认证地址。在主界面、笔记本及工作区配置就绪后显示欢迎卡。登录失败、配置不可访问、笔记本加载失败时不会自动显示。点击 **Start guided task** 开始，**Maybe later** 暂时跳过。

顶部 **Help & guided tours** 提供核心任务、部门研判说明和报价说明。**Continue tour** 恢复当前任务；重播核心任务不会自动导入、命名、保存或下载。在当前示例笔记本中，样例准备步骤允许直接 Next 复用已存在的样例。**Reset this notebook’s tour** 在帮助卡展开后重置引导；不改业务数据。

## 真实任务

| 阶段 | 用户实际操作／阅读 | 推进依据 |
| --- | --- | --- |
| 准备 | 点击 Open sample notebook；有未保存内容时明确选择保存、丢弃或取消 | 样例导入、创建原生会话、保存书签均成功 |
| 整合 | 点击 Cross-department master | 当前批次总表请求成功且非空；已有视图也核对已加载结果 |
| 理解 | 阅读完整性与待确认计数 | 阅读型 Next |
| 差异 | 展开 Open questions；停留阅读部门分歧 | 展开事件，再通过独立阅读步骤继续 |
| 依据 | 点击真实数值单元格 | 展示该单元格的文件、工作表、原件行或公式依据 |
| 原件 | 点击 Open original source | 同批次对应部门原件加载成功 |
| 核对 | 展开 File provenance；停留阅读文件与行号 | 展开事件，再通过独立阅读步骤继续 |
| 导出 | 点击 Download master xlsx | 服务端生成工作簿成功，浏览器发起下载；最终保存需使用者确认 |
| 留档 | 修改名称并移开焦点；明确点击 Save notebook | 非空名称变更、服务端持久化确认 |

完成卡只在核心任务的必要事件都已成立时显示。客户名称差异仍未解决，下载不是签发；普通研判聊天和实际报告也不混为一谈。部门研判补充引导明确提示模型计费边界；报价补充引导展示真实声明或未配置状态，不声称自动抽取或对外发送已实现。

## 实现结构

- `plugins/src/client/tour/steps.ts`：稳定目标、所属视图、阅读／操作类型；重排需提升引导版本。
- `copy.ts`：复用现有 `[中文, English]` 语言目录；评委默认英文，业务原件保留原始字段语言。
- `state.ts`：版本、状态、当前步骤和必要事件；只接收当前步骤的成功事件，且检查批次一致。不同补充路径单独保留可恢复进度。
- `position.ts`、`tour.tsx`、`style.ts`：真实 DOM 测量、视图等待、遮罩、聚光、卡片、键盘与响应式布局。四块遮罩保留目标可点击；不以固定 sleep 推进路由。
- `master.tsx`：单元格依据是产品的常规功能，教程退出后仍可使用；导出和读取失败提供实际重试按钮。
- `notebook-session.tsx`：在真实持久化确认后发送完成信号；既有未保存修改确认保持有效。

窗口、内部容器滚动、元素尺寸变化、侧栏变化和可视视口变化都会重测。目标缺失会进入有界等待，再展示重试、回到入口与退出；已消失的单元格选择在恢复时回到选择步骤。上一步只回看或打开已有只读视图，不回滚业务状态。错误留在当前步骤，显示真实错误并允许重试。

项目自己的对话框内部渲染同一引导层，键盘同时可访问说明与真实操作控件；Escape 退出并清理监听器、遮罩和临时状态。遇到不属于本项目的原生模态框时暂停退出，不争夺其焦点或绕过权限。聚光动画遵守 reduced motion；小屏卡片可滚动。

## 保存范围与限制

当前 DSH 是共享认证会话，没有员工账户、SSO 或租户隔离。引导不虚构用户身份：以原生笔记本 ID 区分，保存于浏览器标签页的 `sessionStorage`。刷新不自动重播，帮助中可继续；关闭标签页后不保证恢复，浏览器复制标签页可能复制初始存储。未开始、进行中、暂时跳过、完成分别记录。拒绝浏览器存储时只保留本次内存状态，不写敏感业务内容或行为追踪。

这与案例长期保存不同。[案例原件与指纹](../data/mock_business/demo/README.md) 在 Git 中；实际导入的来源／结果在领域服务数据目录，笔记本元数据在 DSH 官方领域存储。安装迁移需一起备份这些目录，教程状态不能代替案例备份。

完整浏览器回归、截图、测试结果和未验证范围统一见 [实测记录](00-status.md#页面内引导与案例留档2026-09-14)。新案例的离线计算和引导通过，不等于该案例的付费四角色研判或真实业务验收通过。

## 2026-09-25 之后的变化

- 首次任务里「下载总表」和「给这次工作起名」改为可选：做了会自动前进，不做可以直接点「下一步」；完成判定只等必做步骤（`Step.optional`）。
- 新增补充线路「示例走一遍」（`cases`）：从「更多示例」打开任意一套示例后，在它的「本月任务」顶部点「带我走一遍这套示例」，五步只读，不调用模型。
- 补充线路不再绑定开始时的批次，跟随当前打开的笔记本；我们自己的预览窗口盖住目标时，引导卡会说明并提供「关闭窗口并继续」。
- 引导之外的常驻帮助：「业务状态」顶部的「现在做什么」、待办上的「怎么处理」、队长的「在哪里」指路，以及「会话与设置 → 使用说明书」（[中文](user-guide.zh.md) / [English](user-guide.en.md)）。
