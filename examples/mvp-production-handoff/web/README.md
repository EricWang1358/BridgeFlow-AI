# 生产部 → 市场部：可操作 MVP v0.2

本版本把 #147 的离线脚本扩展为浏览器工作流。**流程与数据持久化是真实运行的；字段理解与咨询建议使用确定性规则，通知仅本地模拟。** 不是三个已经接通大模型的 Agent，也没有真实员工认证或企业系统接入。

## 相比 v0.1 多了什么

- 中文网页，能实际填写、复核、提交、接收、退回和完成。
- CSV/JSON/单表 XLSX 上传；单条记录、1 MB 上限；空模板明确拒绝。
- Agent 1 交接页：11 字段演示字典、输入输出阶段、映射与规则说明。
- 原值与字段来源、人工补充依据、版本和过程时间线。
- SQLite 持久化，刷新或服务重启不会丢失已保存的记录。
- 提交前复核、版本检查、重复提交防重；未保存的编辑会禁用复核与提交。
- 数据入库和通知状态分开；模拟通知失败可单独重试。
- 市场部可接收、退回、核对后完成；退回修订生成新版本，须重新复核。
- 标准 CSV 导出和数据存放位置提示。
- Consulting 页基于缺项、通知失败、退回等状态给规则建议，并展示跨部门看板。

## 案例及业务假设

依据用户 `生产部.xlsx / Sheet1!A1:K1` 的表头；原件只有表头，无真实业务数据。所有记录均应使用合成或获准脱敏数据。三个数量为不同字段，不擅自等同；本例统一 m³，“方”映射为 m³，实际量定义与生产到市场路由均待真实业务确认。

只演示一条生产交付记录，不做跨部门财务合并，不计算售价、收入、成本、欠款或正式结算。Agent 1 的投票/模板试点在本版本中为显式假设，未实现真实投票或自动流程发现。Agent 3 未自动访谈员工、安排培训或执行咨询措施。

## 打开与运行

当前 Mac：双击同目录 `启动 MVP.command`，访问 http://127.0.0.1:3083/ 。双击 `停止 MVP.command` 可停止，数据保留。与原 BridgeFlow 的 3082 端口独立。

开发者将本目录文件放在同一目录，可运行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py --port 3083
```

核心 HTTP/SQLite 功能使用 Python 标准库；openpyxl 仅用于 XLSX 读取和对应测试。服务只绑定 127.0.0.1，不要将演示服务器暴露为企业生产服务。Mac 后台启动可使用 `.venv/bin/python launch.py start`；其他环境直接运行 server.py。当前机器的双击入口优先复用已有项目 Python 环境。

## 5 分钟演示路线

1. 打开「流程与字典」，确认本案例是固定演示范围和模板。
2. 切到「填报与流转」，点击「载入缺失字段样例」。得到生产量 100、出厂量 98、实际量缺失的记录。
3. 实际量输入 `97.5`，补充依据输入 `演示确认记录`，点「保存补充并校验」。
4. 再填复核结论，点击「确认复核当前版本」。未完成这步不能提交。
5. 可选勾选「本次演示通知发送失败」，点击「提交标准数据」。页面显示具体存放位置和入库版本。
6. 若模拟失败，点「重试模拟通知」。入库不重复，通知转为模拟发送完成。
7. 「演示部门」选择市场部，点「接收并开始核对」。核对后填写结论，点「记录结论并完成」。也可填写原因后退回，切生产部修改并重新复核提交。
8. 查看时间线、下载标准 CSV，再打开「落地建议」，观察不同状态对应的建议。

部门切换是演示控制，不是身份验证。复核与完成操作记录为演示角色，不能当作真实员工签名或权限证明。

## 接口与数据表

| 接口 | 用途 |
|---|---|
| GET /api/state | 演示模板、记录、当前会话防跨站请求标记 |
| POST /api/create | 载入合成样例或解析上传文件 |
| POST /api/docs/{id}/patch | 保存修改、增版本、使旧复核失效 |
| POST /api/docs/{id}/approve | 复核当前完整有效版本 |
| POST /api/docs/{id}/submit | 重校验、标准入库、同事务写通知队列 |
| POST /api/docs/{id}/retry | 仅重试失败的模拟通知 |
| POST /api/docs/{id}/accept | 市场部接收 |
| POST /api/docs/{id}/return | 有原因地退回 |
| POST /api/docs/{id}/complete | 接收后有结论地完成 |
| GET /export/{id} | 导出已入库的当前版本 CSV |

所有变更请求带当前记录 version；旧版本返回 409。缺项或不满足复核条件返回 422。原上传原值不被覆盖，人工变更记录在时间线。SQLite 表：docs（工作记录/当前状态）、submissions（每个入库版本）、outbox（每版本通知及重试次数）。重复提交同一记录版本不会创建第二条数据或通知。重新上传同一文件会创建新工作记录，尚无跨上传内容去重。

状态：草稿 → 待市场部 → 市场部处理中 → 已完成；市场部可以退回，再修改生成新版本。通知失败单独标记，不冒充业务失败或业务完成。

目标系统适配器、真实通知消费者和企业鉴权在后续替换演示实现。当前 Host/Origin 与防跨站标记仅是本地保护，不等于 RBAC/租户隔离。文件只保存在本机解析，未调用外部模型或 OCR。

## 验证记录

运行 `python test_flow.py`，使用独立临时数据库，不污染演示数据。已通过 12 组流程断言：

1. 缺失阻断入库。
2. 补充后仍需复核。
3. 入库与通知失败分开记录。
4. 重复提交不重复入库或通知。
5. 通知独立重试。
6. 退回修订、旧复核/旧版本失效。
7. 市场部接收并完成。
8. CSV 上传与空模板拒绝。
9. 负数量拒绝。
10. XLSX 解析（内存中的合成测试表）。
11. 数据库重开恢复。
12. 标准 CSV 导出。

已额外在浏览器实际操作：载入 → 补 97.5 → 复核 → 入库及模拟通知失败 → 重试 → 市场部接收 → 填写核对结论 → 完成 → 查看咨询建议与最终看板。结果为一条已完成记录；真实模型调用和真实消息发送均为零。

## 交付边界

v0.2 是独立本地交互 MVP，不是已合入 BridgeFlow 主应用的功能。单文件单记录、单个流程；不支持多行批量、多表合并、图片 OCR、真实大模型推理、企业账号、外部数据库或飞书通知。所有“模拟发送完成”仅表示本地演示分支执行成功。

本地 `data/` 不进源码包或 issue：其中包含运行数据库、日志和进程信息。GitHub 同步说明、源码和验证结果，不发布用户上传文件或数据库。
